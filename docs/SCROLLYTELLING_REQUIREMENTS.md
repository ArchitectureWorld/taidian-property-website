# 泰典物业滚动叙事官网设计要求

## 1. 产品定义

本项目的动态官网方向统一定义为 **滚动叙事（Scrollytelling）**。

滚动叙事不是单纯在网页中加入自动动画，也不是把滚轮当作翻页按钮。它是以滚动进度作为叙事时间轴，让文字、视觉对象、空间关系和背景过渡共同推进品牌故事。

技术层级可以继续使用以下术语，但不能替代产品定义：

- 固定舞台：Sticky Scene；
- 滚动驱动动画：Scroll-driven Animation；
- 滚动擦洗：Scroll Scrubbing；
- 阻尼跟随：Damped Scroll Progress。

## 2. 核心传播目标

完整滚动叙事需要让访问者依次理解：

1. **泰典物业是谁**：一家长期服务住宅社区的物业公司；
2. **经验为什么重要**：经验最终体现为更早、更准确的判断；
3. **为什么尤其懂老旧社区**：能够理解设施、空间、居民和多方协同之间的复杂关系；
4. **为什么更具性价比**：通过经验、流程和数字化减少试错、重复与等待；
5. **为什么值得长期合作**：科技提升效率，稳定服务最终回到居民的日常体验。

## 3. 五章叙事结构

| 章节 | 叙事任务 | 视觉任务 |
|---|---|---|
| 001 序章 | 建立“泰典物业”品牌识别 | 动态主体从初始状态进入可识别的社区系统 |
| 002 经验 | 说明经验如何形成判断能力 | 结构逐步稳定、层级变得清晰 |
| 003 老旧社区 | 展示对复杂既有社区的理解 | 节点、建筑或真实场景被重新梳理 |
| 004 效率价值 | 解释科技与管理如何形成高性价比 | 路径缩短、连接优化、冗余减少 |
| 005 长期共建 | 形成长期合作与品牌收束 | 所有关系汇聚为稳定、持续运行的系统 |

五章必须构成连续因果关系，不能只是五张互不相关的视觉状态。

## 4. 滚动交互要求

- 向下滚动：叙事向前推进；
- 向上滚动：叙事连续倒放；
- 停止滚动：画面停留在当前叙事位置；
- 快速滚动：视觉通过阻尼平滑追赶目标进度，不直接跳帧；
- 章节按钮：仅用于快速定位，不能取代滚动叙事；
- 文字、动态主体、章节编号、进度条和背景必须使用同一显示进度；
- 不使用自动轮播作为主要叙事方式。

## 5. 章节过渡要求

- 视觉状态使用连续插值，不允许在章节边界瞬间切换；
- 中文文案采用交叉淡化和短距离位移，避免多段文字长时间重叠；
- 背景颜色、图片明暗与下一章节空间必须提前交接；
- 固定舞台退出时需要有独立的退场区间，完成缩放、位移、透明度和背景接管；
- 最后一个动态章节与后续普通内容之间不得出现硬切背景。

## 6. 性能要求

- 滚动事件只更新目标进度，渲染统一交给 `requestAnimationFrame`；
- 使用与帧率无关的阻尼算法生成显示进度；
- Canvas 在高分屏和移动端限制设备像素比；
- 光晕、粒子纹理等重复资源优先缓存，不在每一帧重新创建；
- 稳定后停止无意义重绘；
- 避免大面积实时模糊、滤镜和高成本阴影；
- 动效必须提供 `prefers-reduced-motion` 降级方案。

## 7. 当前视觉母题分支

- `concept/community-life-network`：社区生命网络滚动叙事；
- `concept/architectural-wireframe`：建筑空间模型滚动叙事；
- `concept/community-digital-overlay`：真实社区数字图层滚动叙事。

这些分支比较的是不同视觉母题，交互架构与五章叙事标准必须保持一致。

## 8. 验收标准

正式进入主线前，至少需要满足：

- 页面标题、说明和开发文档统一使用“滚动叙事 / Scrollytelling”；
- 五章内容完整，且顺序符合品牌逻辑；
- 滚动可前进、倒放并停留在任意中间状态；
- 动画无明显跳帧、突变或章节硬切；
- 底部背景能够连续交接；
- 桌面端与移动端均无横向溢出；
- 浏览器控制台无错误；
- 正式站 `main` 在方案确认前不合并任何概念分支。
